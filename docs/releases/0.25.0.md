# illogical 0.25.0

**The bridge to Arugula.** illogical is being renamed Arugula (#509). This
release still calls itself illogical, and nothing you see changes. Update
every machine to it before the renamed release comes out: from here on,
a renamed CLI, app or daemon works with this one, and this one's
*Update now* installs the renamed release when it's out.

Update: *Update now* in the page, `illogicald update`, or
`curl -fsSL https://illogical.widgets.wtf/install.sh | sh` (on Windows,
`irm https://illogical.widgets.wtf/install.ps1 | iex`). Panes keep
running.

## New

- **Both names, wherever versions meet** (#504):
  - The daemon takes the renamed CLI's headers, and control takes the
    renamed daemon's signature header. The check that tells an agent
    from the owner works under either name.
  - `ARUGULA_*` variables work wherever `ILLOGICAL_*` ones do.
  - The daemon updates itself to a release whose binaries are named
    `arugula` and `arugulad`.
  - `illogical status` and the app's Daemon menu find an `arugulad`
    service.
- The HTTP routes the web client calls answer with types from `proto`
  (#445), and the daemon and control share their enrolment, routing and
  relay messages in one crate (#449). Neither changes what you see.

## Kept as they are

The names that stored keys, signatures, running panes and sandboxes
depend on stay "illogical" after the rename. Nothing has to be enrolled
again because of them. DECISIONS.md lists them.
