# illogical 0.12.0

Fountain, more deeply: your Fountain agents as a catalog (#121), any of
them worn by a Claude Code here (#122), and a machine of yours as the
account's Fountain runner, whose conversations you can open, diff and
take over (#123). Also: headless `claude -p` no longer waits on
illogical's hooks (#124), and no MCP token is on a command line any more
(#128).

Install or upgrade: `curl -fsSL https://illogical.widgets.wtf/install.sh | sh`

## New

- **Fountain agents** (`illogical fountain`, *Fountain agents…* in the
  `+` and pane menus, MCP `open_fountain`): every agent on your account
  as a card, with its model, skills, MCP servers and environment. You
  can search and filter by where it comes from (agent-specs, hand-made,
  made by an app), runtime and provider. It reads with your own
  `fountain` login, and the key stays in memory.
  - *Run on Fountain* opens it as an agent block beside the catalog.
  - *Spec* opens the agent-specs file that declares it.
  - MCP `list_agents` and `read_agent` let any agent here see the team
    and hand a task to one through `start_agent`. Header and env values
    that aren't `${…}` references come back as `<redacted>`.
- **Run here: wear a Fountain agent locally** (*Run here*,
  `illogical agent --as NAME`, `start_agent {as_fountain}`): a Claude
  Code block here with the agent's system prompt, its skills (as a
  plugin) and its MCP servers.
  - `${VAR}`s resolve from Infisical through agent-specs' environment
    and vault mapping, then your shell's environment, then `gh auth
    token`. The values are held in memory and scrubbed from logs and
    transcripts.
  - A server that needs an OAuth sign-in, or a variable nothing
    provides, is left out, and the block's header says which and why.
  - An agent tagged `illogical.local: false` (one written for Fountain's
    sandboxes, such as an orchestrator) is refused with that reason.
    Claude agents only for now.
- **A Fountain runner on your machine** (Linux):
  - `sudo bash scripts/fountain-runner-setup.sh` sets up a `fountain`
    user, a systemd unit and a narrow sudoers rule. Then `illogical
    fountain runner install` creates the runner's key without printing
    it and starts the runner. `status` and `adopt` follow from there.
  - The unit hides other users' processes from its sandboxes
    (`ProtectProc=invisible`) and keeps them out of your home.
  - **The runner view** (`illogical fountain --view runner`) shows the
    runner's status and version, and each sandbox with its
    conversations. It raises *Fountain runner offline* when the unit
    runs but Fountain hasn't heard from it for 5 minutes, and warns when
    another runner is online (it would get the conversations).
  - From a sandbox's card:
    - *Follow* reopens its conversation (never a new one);
    - *Changes* diffs each checkout in it;
    - *Shell* opens a terminal there as `fountain`.

    Every read of a sandbox ignores repository config that could run
    code, and never fetches.

## Fixed

- `claude -p` and the Agent SDK no longer hang on illogical's
  `SessionStart` hook: `illogical inbox` leaves a session nobody drives
  at once (#124).
- **No MCP token on a command line.** claude-agent-acp's SDK puts its
  MCP config on `claude`'s command line, which any local user can read.
  illogical's own token, and a worn agent's secrets, now go there only
  as `${…}` references, with the values in the adapter's environment
  (#128).
- A Claude block resumed after a daemon restart keeps
  `settingSources: []`, as a fresh one does, so your user hooks don't
  load into it (#127).
- An agent on a machine (a guest's, say) can create terminals, agents
  and blocks only on machines, never on this host, through every MCP
  tool that creates one.
