# illogical 0.6.2

Your Claude Code conversations as blocks, and blocks on illogical
control's page.

Install or upgrade: `curl -fsSL https://illogical.widgets.wtf/install.sh | sh`

## New

- **Claude Code conversations as blocks** (M33, #72).
  - **What's indexed:** each machine's daemon indexes the Claude Code
    sessions on that machine: terminal ones, and the desktop app's Code
    tab, with its titles and archiving. It also notes which sessions are
    live right now, including the pane one is running in.
  - **Opening one** gives a stopped agent block with its transcript. While
    the session is live somewhere else, the block follows it read-only, so
    you can watch a terminal session from the phone.
  - **Continuing:** *Continue* resumes a conversation that isn't running,
    with your settings and CLAUDE.md, hooks off, and its last model. One
    that's live in a pane offers *Go to pane*. One that's live anywhere
    else offers *Fork*.
  - **Ways in:** a *Conversations* picker on the web and in the TUI;
    `illogical claude ls` and `illogical claude open <id>`;
    `illogical agent --resume <id>` and `--fork <id>`; and the MCP tools
    `list_conversations` and `open_conversation`.

## Fixed

- **Editor and browser blocks on control's page** (#69). On
  `control.illogical.widgets.wtf`, VS Code blocks and browser blocks were
  refused with a CSP error. Two rules refused them:
  - **The daemon's side:** a block allowed only the daemon's own pages to
    frame it. While the daemon is enrolled in control, control's page may
    frame its blocks too.
  - **Control's side:** control's page allowed frames only from itself.
    Now any https site may be framed there, as on a daemon's own page. A
    framed site still can't read control's page.

Blocks still load straight from their machine's tailnet address, so
through control they work on devices on your tailnet.
